## 2. 这轮证明了什么

1. 输出纪律生效：不再出现 `finish_reason=length`；
2. 重复检测与终止在真机生效：模型收到“换假设”后仍复读，系统按规则终止，而不是空转到预算耗尽；
3. 但也证明：**没有语义反馈时，“换假设”只是口号**——模型不知道第 1 轮为什么没触发，只能重复。

## 3. 为什么建议停止

- 连续三轮（S5-b1/b2/b3）都卡在同一处：模型能给出合法长度、能基于种子变异一次，但拿不到“解析到哪一步失败”的信号；
- `Fuzz_chpw` 的 harness 不输出解析错误，`krb5_chpw_message` 的返回值也被 harness 丢弃，B3 在当前镜像里**没有可用反馈源**；
- 继续投入的边际收益低，而 S5 还差 7 个独立高危案例。

## 4. 建议的下一步

1. **停止 CG-09 迭代**，把它保留为“能力边界”的诚实记录（`generated_but_unverified`）；
2. 把资源转向 S5 案例池：优先处理有构造器/有种子、能拿到语义反馈的任务；
3. 若坚持要攻 CG-09，需要先给 harness 打补丁输出解析结果，或用外部实现（python-krb5）生成合法 ASN.1 种子——都超出“不改目标程序”的边界，应单独立项。

**一句话：B5 修好了，但这条路的天花板是“harness 不给反馈”，不是模型不努力。**
