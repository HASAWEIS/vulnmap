## 1. 为什么换掉 harfbuzz

原首选 `arvo:42471192`（harfbuzz，`Script::subset` 序列化越界）需要构造带特定 GSUB/GPOS 表的字体，
手工成本高；`arvo:42485152` 是**纯文本配置解析**，缺陷点是一行判定缺失。两者镜像都可得，
按“谁能更早形成完整证据包”选了 haproxy。harfbuzz 仍作备选，未计数。

## 2. 触发原理

```text
1869 fgets(thisline + readbytes, linesize - readbytes, f)
1882 end = line + strlen(line);
1909 *(end - 1) = 0;          // kill trailing LF
```

首字节为 `\x00` 时，`fgets` 读到的字符串长度为 0，于是 `end == line`，
`*(end - 1)` 落在 `thisline[-1]` —— 堆块左侧 1 字节越界写。

两个必要条件（都踩到了）：

1. `fuzz_cfg_parser` 有 `if (size < 50) return 0;`，所以 PoC 必须 ≥50 字节；
2. 首字节必须是 NUL，否则 `strlen(line) > 0`，不会出现 `end == line`。

实测栈与 ARVO 记录一致：

```text
#0 readcfgfile /src/haproxy/src/cfgparse.c:1909
#1 LLVMFuzzerTestOneInput /src/haproxy/fuzz_cfg_parser.c:38
```
