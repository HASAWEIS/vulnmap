## 1. 怎么跑的

```bash
# 1) 复制 workspace（80M），删掉 .runtime，换新 run_id
cp -a workspace/S7-CG18-arvo-12420 experiments/cg18-newrun-20261126/ws
rm -rf experiments/cg18-newrun-20261126/ws/.runtime
# task.json: run_id=r-cg18-ledger-20261126, verify.allow_builders=false

# 2) 开账本，走真实模型，只跑 verify
export DEEPSEEK_API_KEY=*** LLM_MODEL=deepseek-chat LLM_BASE_URL=https://api.deepseek.com/v1
export VULNMAP_LLM_LEDGER=experiments/cg18-newrun-20261126/calls.jsonl
python3 bin/vulnmap.py run experiments/cg18-newrun-20261126/ws \
  --stages verify --max-turns 20 --max-requests 12 --max-tokens 300000
```

为什么 `verify.allow_builders=false`：预置构造器（agent/builders/libidn2.py）会直接
给出可用输入并 pass，从而**跳过模型闭环**；那样就没有任何 LLM 调用，也就没有参数可记。
强制走模型路径，才有真实调用可对账。

## 3. 为什么 D2 还是 false

CG-18 的 D2 要求是：**决定性的那批调用**（产出交付 PoC 的调用）有完整参数。
本次运行：

- 模型闭环跑了 3 轮，产出候选但**全部未通过双端**；
- 因此交付 PoC 不是这次模型调用的产物；
- 账本 complete 只说明“这次调用发了什么”，不能替代“决定性调用有参数”这条。

历史记录仍是 missing；本次新记录**单独归档**，不合并进旧 run，也不改旧 case.json。

## 4. 这份记录能证明什么 / 不能证明什么

能证明：

1. 课程验证入口会在真实路径上写账本，且 run_id/call_id 可与轨迹对齐；
2. 账本记录的是实际发送值（max_tokens=8000 与请求体一致），并有请求/响应哈希；
3. 账本不含凭据；
4. 参数证据缺失时 VerifyStage 会判 incomplete（见 tests/test_verify_call_ledger.py）。

不能证明：

1. CG-18 的 D2 已通过；
2. 模型能自主构造 libidn2 的越界输入（3 轮均未通过）；
3. 任何漏洞结论的变化（verdict 仍是 generated_but_unverified）。
